# Draft or change the mission

MISSION.md says what the product is, independent of any version. Every agent reads it on every assignment, and every other project document must agree with it. A version's documents decide what that version delivers; the mission decides what the product is.

## Where it goes

`<team>/.project/documents/concept/MISSION.md`, one file. Honor an existing canonical location.

## When to use it

Use it when the owner asks for a mission, when a project starts and the owner has described what the product is, or when the owner wants an idea added to it. Ideas from a discussion, a diary entry, or a worker's suggestion stay proposals until the owner approves them through this skill. Never change the mission to make a version, a plan, or an implementation fit.

## Draft from the owner's words

Work from what the owner has said: the conversation, a founding brief, or diary entries the owner points to. Adapt [the template](templates/MISSION.md). Keep the owner's own phrasing for decisions where it is clear. Do not research, invent goals, or add features. Where the owner's words leave something consequential open, ask rather than fill it in. Name each reference the owner has given, a codebase or an image, and what it is the reference for, so roles carry it over instead of designing. For the few things the product exists to prove, write what it is, the fake that would pass every check while missing the point, and the test that tells them apart; the intent review judges work against these.

Write for every agent's repeated reading: plain prose and short lists, no tables, at most about 800 words, and shorter is better. State lasting structure concretely enough to check, such as the regions an interface always shows or the boundary between two programs, because roles verify work against these lines. A part that a version leaves out is still part of the product; say so where it matters. Leave out version scope, schedules, implementation details that may change, and history.

## Approval

Show the owner the full draft or, for a change, the exact lines added, removed, or replaced, with one sentence on why. Save only after the owner's explicit agreement, and save exactly what was agreed. If the owner edits the text, the edited text is what was agreed.

A change to the mission can make version documents wrong. List the documents that now conflict with it and route them to their owners. Do not rewrite them in the same step.

## Finish

Return the path and any conflicting documents, then stop.
