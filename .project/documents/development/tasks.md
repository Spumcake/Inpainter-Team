# Simple Sketch — delivery

**Sources:** [Pitch](../PITCH.md), [interface](../../../INTERFACE.md), and [systems](systems.md). The renders are in `.project/renders/ui/`, listed in the interface.

**Objective and exclusions:** A person can open the desktop app, draw pressure-sensitive smoothed vector strokes on canvas objects whose palette colors are their layers, erase part of a stroke without destroying it, and undo. The first version also includes the pictured shell, the properties panel, the Layers outliner with groups, shapes, text, selection and transforms, the in-app clipboard, tabs, and saving a sketch as a `.smx` file the person chooses. Phone layouts, collaboration, accounts, cloud sync, printing, brush flow, and eraser opacity are out.

**Version convention:** No release version is agreed. Do not tag a candidate until one is. After a version is agreed, candidates use `<version>-candidate.<n>`.

## Acceptance criteria

SS-1 Brush. On a new sketch the brush draws on Canvas 1 at once, into the layer that came from the active brush color. A drag that reports pressure, with Pressure affects size on, leaves a stroke that is thinner where pressure is lower, shaped by the pressure curve. A drag with no pressure, or with the option off, uses the full size the Size slider shows: the layer's size while the brush color's Lock size is on, or the slider's value once it has been moved. Moving the slider never resizes a stroke already drawn. A stroke keeps its samples exactly as reported and keeps the brush settings it was drawn with. The brush and eraser can always be chosen. With no visible, unlocked canvas highlighted, a brush stroke makes a new canvas holding it, in one undo step, and the eraser erases nothing. A brush drag draws nothing while the layer it would draw into is hidden or locked.

SS-2 Eraser. Dragging the eraser across part of a stroke on the highlighted canvas hides only the ink inside the eraser path, at the eraser's size, which narrows with pressure when that option is on. The rest of the stroke stays, with its samples and identity. Strokes drawn afterward stay fully visible. Undo shows the hidden ink again. Moving the canvas moves the hidden portion with it. Hidden or locked colors, other canvases, shapes, and text are not erased.

SS-3 View. Pan and zoom change the view and leave stored geometry unchanged. Zoom stops at 12.5% and 800% of the default. Fit frames visible objects. A sketch with nothing visible returns to the default view centered on the origin. Zoom to selection frames the selection. Pan and zoom are not undo steps.

SS-4 History. Each finished change listed in the interface's History section is one undo step on the active sketch, and undo then redo restores it. A new step clears redo. A press too short to be a stroke, a miss with the eraser, and changes to the view, selection, the active brush color, tool settings, tool palettes, the Size slider, or the panel do not enter history.

SS-5 Shell. The window follows `base-ui.png` with the toolbar order in the interface. It has the current tool's palette swatches, with the brush's active color marked, New sketch, Open, and Save, undo and redo, the seven tools, the Size row, and zoom out, zoom in, fit, and a maximize toggle. Labels, icons, shortcuts, and hover text all come from one registry. Each tab keeps its own objects, selection, view, and history. The current tool, tool settings, and the panel state stay across tabs. The window always keeps one sketch. Closing the only clean sketch does nothing.

SS-6 Shapes and text. A rectangle, ellipse, or line commits a shape object, selected, at the top of the sketch with a copy of the tool's palette (Outline and Fill, or Stroke), its width from the Size slider, and the tool's corner radius. Constrain proportions, with Shift inverting it, gives a square, a circle, or 45-degree steps. Snap to grid lands the drag on grid points. Text commits a text object with the tool's font, size, emphasis, alignment, spacing, caps, auto-size, and wrap, and a copy of its Text, Background, and Border palette, including line breaks. Changing a selected text object's font size in the panel resizes it, and so does the toolbar's Size slider while the text tool has it selected or is editing it; otherwise the slider sets the next text's size. A text's edge handles set its box's width and height, and its lines sit at the top, middle, or bottom of a taller box. An empty text commit is discarded.

SS-7 Keep. Save As stores the active sketch as a `.smx` file the person chooses, including its objects, palettes, strokes, erasures, and view, so a later open of that path returns it unchanged. Save writes that path. Save As moves later saves. Save a Copy writes another file and leaves Save aimed at the original. Opening a path that is already open focuses its tab. A sketch with unsaved changes asks once before it closes. Discard drops those changes and that sketch's recovery file. Save then close keeps the file. While the sketch is dirty, a recovery copy is written every 10 minutes and does not modify the `.smx`. The next launch can restore it without writing the `.smx` until the person saves. Tool settings and the default palette persist across sessions separately from sketches.

SS-8 Palettes and canvases. Every creation tool has its own palette, kept as a tool setting: nine colors for the brush, Outline and Fill for the rectangle and ellipse, Stroke for the line, and Text and Background for text. Every object copies its tool's palette when it is made and keeps its own afterward, so tool edits change only what comes next. A canvas's palette colors are its layers: a layer earlier in the palette paints above every later one, and reordering the palette reorders the layers. A layer owns its value, opacity, size, dash, cap, visibility, and lock. Editing a layer restyles its strokes without changing samples, a size edit restyles only strokes that follow the layer's size, and overlapping strokes in one layer do not darken each other. A stroke whose brush color has no layer on the canvas adds one. Make palette default copies a canvas's palette into the brush's. A canvas's bounding box is its visible ink bounds plus its padding. Duplicate, delete, and move work on brush colors and layers, the shape and text roles are fixed, and every palette keeps at least one color.

SS-9 Properties panel. F4, the panel's tab, and Properties in a tool's or swatch's right-click menu open the panel as the interface describes, and it starts closed. The panel follows the current tool. Every palette color, whatever owns it, opens the one color page, with Visible on every color and Lock size on a tool color that has a size. A selected shape or text object shows its Palette section; a tool's page does not. Every page shows the sections listed in the interface, built from one schema, and uses the same chrome: the edge tab, no Properties header, no close button, and no tool-name and description card, even where a render still draws those. That includes shape, text, and Layers. Tool settings are defaults that persist and are not undo steps. Color and object edits are undo steps. A multi-selection shows only shared sections, and mixed values are marked.

SS-10 Objects and layers. The select tool picks whole objects, including groups, by visible ink, fill, or text box. It marquees, moves, scales, rotates, nudges, and deletes. The context actions bring to front, bring forward, send backward, send to back, align, group, ungroup, rotate, and flip. Zoom to selection is a shortcut. The outliner shows the tree with eyes, locks, renaming, drag to reorder and regroup, and canvas color rows, always in step with the canvas selection. Hidden objects are not drawn or picked. Locked objects are not picked on the canvas or changed. Group then ungroup keeps every object where it was. Copy, cut, and paste copy whole objects with an offset and select the duplicates.

## Development and preview

The app repository is `vector-sketch` at https://github.com/Spumcake/vector-sketch. Its bare clone is `src/vector-sketch/worktrees/.bare`, and the permanent checkout is `src/vector-sketch/worktrees/dev` on branch `dev`. From that worktree, `cargo test` runs the session, document, and egui-frame tests, and `cargo run` opens the window. Use `cargo run --release` to judge performance. The Linux packages are in the app README.

Preview: open the window, draw on Canvas 1, change and reorder colors, erase, undo, add a shape and text, select and group them, open the panel, and pan, zoom, and fit. A new sketch has one empty canvas. There is no seed drawing and no network service.

## Verification and delivery

The session and document rules behind SS-1 to SS-4 and SS-8 to SS-10 belong in unit tests, along with the tab and close rules in SS-5 and the save-identity rule in SS-7. So do the registry and schema checks in [systems](systems.md). Appearance, smoothing, and whether an erase follows its path are a human preview of `cargo run`, not a mesh snapshot. Check levels and the release-test brief are in [testing.md](testing.md). No every-commit workflow is installed. No version is agreed, so no candidate is recommended.

Implementation follows the slices in systems and the order in the plan. Task-operations owns implementation and integration in the app. The branch-manager is the only role that changes Git state, and commits only when the owner asks. Nothing is deployed. The owner pushes and tags.
