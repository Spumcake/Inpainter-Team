## Attempts and result

Copy, cut, and paste use a clipboard on the window. Ctrl+C copies the selection. Ctrl+X copies what can be deleted and deletes it as one undo step. Ctrl+V inserts new ids at the root top, offset by (16, 16), then another (16, 16) on each repeat, and selects the duplicates. A canvas copy keeps its palette, strokes, and erasures. A group copy keeps its children. These commands are not toolbar buttons and do not use the operating-system clipboard.

The five points the documents left open were built from readings, not from an owner decision: an empty paste does nothing; a selected child of a selected group is copied once inside the group; a locked object can be copied and is not deleted by cut; undo of a cut leaves the clipboard full; the object clipboard does not run while text is being edited.

Review found no defects. Two readings it noted, which the contracts do not contradict: undo of a paste does not rewind the repeat offset, and a mixed cut copies only the objects it can delete.

The window check launched the current sources. The Wayland window could not be addressed, so the check relaunched on X11 and sent events only to the Simple Sketch window id. R reached that window. A drag sent the same way created no rectangle, because this build takes pointer buttons from XInput2 and those events do not fit a message to the window id. The seat pointer was not used.
