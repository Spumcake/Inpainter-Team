These files stay as they are, and this map does not copy them again: `host/src/window.rs` (title Inpainter, `APP_ID` `io.github.spumcake.Inpainter`), `host/src/tabs.rs` (the strip, the menu button, the plus, the close mark), `host/src/toolbar.rs` (the empty bar, `install_fonts`, `paint_icon`, `glyph_button`, `hairline`), `host/src/panel.rs` (the column, `WIDTH`, `toggle_tab`), `host/src/grid.rs` (`paint_grid`, `GRID_SPACING`), `host/src/widgets.rs` (colors, `Scale`, menu rows, chevrons), `host/src/icons.rs` (until the registry edit below), `host/assets/fonts/`, and `host/assets/icon/`. `host/src/process.rs` already starts one child from the manifest and speaks the declaration through `end`. `protocol/src/lib.rs` stays JSON Lines, one object per line, a `type` field, and `PROTOCOL_VERSION` of 1. What it cannot say yet is listed under New.

The shared library is a new workspace member, crate `sketch`, at `sketch/`. The host package `inpainter` and the app package `simple-sketch` both depend on it. Neither depends on the other. Drawing, erasing, shapes, text, and ordering run in the host, on its copy, so pen samples never leave the process. The simple-sketch process is the one that commits arrangement, `.smx` save, and undo. After that process commits, the host replaces its sketch nodes and camera from the document that process sends. `document/snapshot.rs` `Sketch::snapshot_value` is that document: `format_version` 1, id, name, camera, and nodes. History, selection, the clipboard, tool settings, and the panel are not in it, and they stay out of it.

## New, approved by the owner on 2026-10-14

- The `sketch` crate (`sketch/Cargo.toml` and `sketch/src/lib.rs`). The reference is one program. The host has to run drawing, erasing, shapes, text, and ordering without depending on the app crate, and the app has to own arrangement, save, and undo without depending on the host. The reference has no second library for that.
- Messages on the existing protocol so three things can cross the process. The app sends the document after `end`, using `Sketch::snapshot_value`, and the host replaces its nodes and camera from it. The host sends a command, and the app applies it with the same `Session` method the host uses, which is also how Simple Sketch is driven with no host process running. The app sends the menu, toolbar, and property rows it builds from `registry` and `schema`. `protocol/src/lib.rs` has none of these. `AppMessage` is `Hello`, `Tab`, `Contents`, `Panel`, and `End`. `HostMessage` is `Shutdown` only. `ContentsKind` is `Grid` only. `PanelSide` is `Right` only. `Running::apply` drops every line once the declaration is no longer pending. The framing stays JSON Lines, one object per line, a `type` field, and `PROTOCOL_VERSION` 1.
- A status in the host window when the sub-application has exited or stopped responding. The window stays open and the shell stays usable. The reference has no status view, no wording for it, and no timer. Nothing in `src/simple-sketch` treats a live process as not responding. `Running::exited` records that the child has left, and the host does not draw it. The renders cited by `INTERFACE.md` do not show this status.
- A check that fails if the host package `inpainter` and the app package `simple-sketch` depend on each other. The reference is one crate and has no such check.
